# 검사성적서 관리 웹앱

입고 제품의 검사성적서를 등록·조회하고, 검사성적서 양식으로 인쇄/PDF 저장까지 하는 사내용 웹앱입니다.
Node.js + Express 로 만들었고, 데이터베이스 없이 JSON 파일과 로컬 디스크에 저장합니다.

## 두 가지 화면

| 화면 | 주소 | 무엇을 하나 |
|---|---|---|
| **관리 화면** | 사내 PC에서 실행하는 서버 (`http://<사내IP>:3000`) | 등록 · 수정 · 삭제 · 사진 업로드 · 성적서 인쇄 |
| **공개 조회 페이지** | GitHub Pages | 읽기 전용 현황 조회 (사진·상세 내용 없음) |

공개 조회 페이지는 **실시간이 아닙니다.** 사내 PC에서 데이터를 내보낸 시점의 스냅샷이며,
페이지 상단에 "데이터 기준" 시각이 표시됩니다.

## 주요 기능

- 성적서 1장에 **품목 여러 개** 등록 — 품목마다 판정(적합/부적합/조건부적합)·사진·불량내용·비고를 따로 기록
- 종합판정 자동 계산 — 품목 중 하나라도 부적합이면 성적서 전체가 부적합
- 문서번호 자동 채번 (`퍼시스-시험YY-MM-NNNNN`) — 그 해 마지막 번호 다음으로 이어짐
- 기간·업체명·품목명·검사결과 필터, 리스트 뷰 / 갤러리 뷰
- 검사성적서 양식 출력 (인쇄, PDF 저장)
- CSV 내보내기 / 불러오기 — 품목마다 한 줄, 같은 문서번호는 한 성적서로 묶임
- 입고예정 등록 및 검사 완료 시 자동 정리

## 실행 방법

```bash
npm install
node server.js        # 또는 서버시작.bat 더블클릭
```

`http://localhost:3000` 으로 접속합니다. 같은 사내망의 다른 PC에서는 `http://<이 PC의 IP>:3000`.

포트나 데이터 위치를 바꾸려면 환경변수를 씁니다 (기본값: 3000 / `./data`).

```bash
PORT=4000 DATA_DIR=./testdata node server.js
```

## 데이터 구조

`data/inspections.json` 한 건이 성적서 1장입니다.

```jsonc
{
  "id": "...",
  "inspectionNo": "퍼시스-시험26-09-00044",
  "inspectionDate": "2026-09-15",
  "vendor": "업체명",
  "inspector": "검사자",
  "inspectionItem": "외관 및 치수",
  "criteria": "검사 기준 (여러 줄)",
  "items": [                               // 품목 목록
    {
      "itemName": "...", "color": "...", "lotNo": "...", "quantity": 1,
      "result": "적합",                     // 품목별 판정
      "defectDetail": "", "remarks": "",   // 품목별 불량내용 / 비고
      "photoUrls": [], "defectPhotoUrls": []
    }
  ],
  "remarks": "성적서 전체 비고",
  "result": "적합"                          // items 로부터 자동 계산
}
```

`itemName`·`color`·`result`·`photoUrls` 같은 값은 첫 품목 기준으로 자동 생성되어 함께 저장됩니다.
예전에 품목 1개 구조로 저장된 데이터는 읽을 때 자동으로 `items` 형식으로 변환되므로 그대로 호환됩니다.

사진은 `data/uploads/<성적서 id>/` 아래에 저장됩니다.

## 공개 페이지 갱신

사내 PC에서 아래를 실행하면 공개용 요약 데이터를 다시 만들어 GitHub에 올립니다.

**`깃허브_업데이트.bat` 을 더블클릭**하면 끝납니다. 내보내기 → 기록 → 업로드를 한 번에 합니다.

명령으로 직접 하려면:

```bash
node update-github.js          # 위 배치 파일이 실제로 실행하는 것
```

> 배치 파일에 한글을 넣으면 Windows 명령창 인코딩 때문에 글자가 깨져 실행이 실패한다.
> 그래서 `.bat` 은 영문 4줄만 두고 안내 문구는 모두 `update-github.js` 에서 출력한다.

**공개 페이지에 나가는 항목**: 문서번호, 검사일자, 업체명, 검사자, 품목명, 색상, 수량, 판정

**나가지 않는 항목**: 사진, 불량내용, Lot No., 비고, 검사의뢰서/ERP 링크

무엇을 내보낼지는 [`export-github-data.js`](export-github-data.js) 에서 바꿀 수 있습니다.

## 폴더 구조

```
server.js                 Express 서버 (정적 파일 + API)
public/index.html         관리 화면 (대시보드 + 등록/수정)
public/report.html        검사성적서 출력 양식
export-github-data.js     공개용 요약 데이터 생성
update-github.js          공개 페이지 갱신 (내보내기 + 업로드)
docs/                     GitHub Pages 로 게시되는 읽기 전용 페이지
data/                     실제 데이터와 사진 (저장소에 올리지 않음)
```
